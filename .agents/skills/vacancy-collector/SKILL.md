# Vacancy Collector

## Назначение и вход

Применяй навык для импорта вакансий или управления статусами записей локального реестра. Прочитай [техническую спецификацию](../../../TECHNICAL_SPECIFICATION.md) для схемы, правил записи и журналирования.

## IMPORT

1. Прочитай локальный файл из `input/`. JSON должен содержать массив вакансий или объект с массивом `items`. CSV должен использовать UTF-8 с BOM или без него и разделитель `;`.
2. Нормализуй записи и проверь обязательные поля `Source`, `External_ID`, `Vacancy_Title`. Для `Published_At` принимай `YYYY-MM-DD` или дату-время ISO 8601 с явным смещением либо `Z`. Отправляй дату-время без часового пояса на уточнение. Отсутствующую дату оставляй пустой. При отсутствии `External_ID` вычисление заменяющего идентификатора запрещено.
3. Для одинакового ключа `(Source, External_ID)` внутри файла и в реестре сравни содержательные поля по спецификации. Игнорируй `Internal_ID`, `Collected_At`, `Record_Status` и `Status_Changed_At`. Нормализуй незначащие пробелы, эквивалентные даты и числа с сохранением смысла текста. Совпадение означает `DUPLICATE`, любое различие после нормализации означает `CONFLICT`. Для новых и некорректных записей применяй `ADDED` и `REJECTED` по спецификации. Направь конфликты и отклонения, включая записи с некорректными датами или отсутствующим `External_ID`, на уточнение.
4. Добавь новые вакансии с последовательным ID начиная с `VC-000001` для пустого реестра, статусом `ACTIVE` и фактической отметкой `Status_Changed_At`. Сохраняй служебные отметки в UTC в формате ISO 8601 с `Z`. При повторном импорте сохраняй существующую запись целиком. Без добавлений не перезаписывай реестр.

## MANAGE

По явному запросу пользователя прочитай `input/record_actions.csv` с полями `Internal_ID`, `Action`, `Reason`. Примени `EXCLUDE` для установки `EXCLUDED`, `ARCHIVE` для `ARCHIVED` и `RESTORE` для `ACTIVE`. Требуй непустой `Reason` для `EXCLUDE` и `ARCHIVE`, для `RESTORE` допускай пустое значение. Отклоняй все команды для ID, который встречается в пакете несколько раз, и обрабатывай остальные корректные команды. При смене статуса запиши фактическое время в `Status_Changed_At` в UTC с `Z` и внеси изменение с причиной в журнал после сохранения. Команда на текущий статус сохраняет отметку и не требует записи реестра, если других изменений нет. Неизвестный ID или недопустимая команда приводят к отклонению строки. Физическое удаление записей запрещено.

## Результаты и проверка

- `data/vacancies_registry.csv` содержит 16 полей в установленном порядке, включая `Record_Status` и `Status_Changed_At`, в UTF-8 с BOM и с разделителем `;`. Используй безопасную запись и защиту CSV от формул по спецификации.
- Для каждого запуска создай JSON-журнал в `outputs/logs/`, Markdown-отчёт и отдельный перечень на уточнение в `outputs/reports/`. Включи общий уникальный `Run_ID` в имя и содержимое каждого артефакта. В журнале фиксируй режим, входной файл, время, счётчики результатов, ошибки, изменения статусов и показатели реестра до и после, включая общее количество записей, количества по статусам и SHA-256 файла. Сохраняй историю запусков без перезаписи.
- Проверь уникальность ключей и внутренних ID, постоянство ID, статусов и отметок при повторном импорте, применение только допустимых пользовательских команд и прослеживаемость отклонений до входной записи.

## Отклонение данных

До изменения реестра проверь весь входной файл и действующий реестр. При повреждении структуры входного файла или реестра прерви запуск, сохрани реестр и запиши причину в журнал. В структурно корректном файле отклоняй ошибочные записи или команды по правилам режима и продолжай обработку остальных. При ошибке записи сохраняй прежний реестр целиком.

## Скрипты

Используй Python 3.13.5 на Windows. После согласования обновления существующего реестра запусти из корня проекта нужную команду.

```powershell
python -B .agents/skills/vacancy-collector/scripts/import_vacancies.py IMPORT input/vacancies.csv
python -B .agents/skills/vacancy-collector/scripts/import_vacancies.py MANAGE
```

`MANAGE` читает `input/record_actions.csv`. Скрипт выводит `Run_ID` и итог запуска. Для отклонённых команд в CSV на уточнение указываются ID, команда, исходная причина пользователя и причина отклонения.
